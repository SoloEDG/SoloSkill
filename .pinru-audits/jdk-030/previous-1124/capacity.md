# jdk-030 困难题容量规划

产品：栈闩工房（机关推箱子）。技术栈 Vue 3 + TypeScript + Vite。
用户覆盖：12 条 0-1 代码生成、12 条 Feature 迭代、不要 Bug 修复。不植入待修缺陷。
规划日期：2026-11-24。基线完成后回填题目 id、源码路径与快照哈希。

## 基线能力（实现后必须具备，题目不得再当成缺口）

- 五模块：`atlas` 关卡地图、`hauler` 箱子推动、`gadget` 地面机关、`ledger` 步数记录、`voyage` 关卡进度。
- 内置多关瓦片地图：墙、地板、目标格、缺口。
- 一次按键移动一格；只能推不能拉；一格最多一个实体；箱子互挡。
- 三种箱子（木、铁、玻璃）只激活对应种类踏板；踏板供电后开门或改变地板（架桥 / 封道）；玩家踩踏板无效。
- 机关在整步落定后同步重算；门关则不可通行；封道激活视为墙；架桥激活把缺口当地板。
- 当前尝试步数、通关后冻结继续移动、重置本关恢复蓝图且不改最佳记录。
- 关卡目录、已完成关最佳步数、localStorage 只持久化记录与当前关卡 id，不保存半局。

基线刻意不含：撤销、幽灵回放、冰块滑行、传送、导出档案、限时、守卫、检查点、激光、双角色、洪水、挂起半局、目标认种类、连环推、延迟门、解锁链、步数拆分、吞箱、单向地板、通关后继续、通关检查机关终态、正反踏板争门、拉取、自锁踏板。也不含统一暂停时钟、完整事件总线、文档快照存档、撤销栈。

降低难度的已有能力核对：

- 无游戏时钟与暂停出口 → 限时、延迟充能仍需自建时间/步相位语义。
- 无跨模块事件流 → 通关、失败、供电边沿不能靠现成总线接入。
- 无完整可复制文档与集中存档 → 撤销、挂起、导入导出、幽灵分世界不能直接扩展副本。
- 重置只重载当前关蓝图，无失效令牌/提交协议 → 成绩提交、检查点、练习模式的写入边界仍是缺口。

## 模块交互（基线至少三处）

1. 推动落定 → 机关按占格重算供电 → 地图通行性变化。
2. 目标格被箱子填满 → 步数簿标记通关 → 进度写入最佳记录。
3. 进度重置 → 地图/箱子/机关回到蓝图 → 步数清零、最佳记录保留。

## 候选总表

下列 24 个目标彼此独立，均从同一冻结基线出发，不依赖先完成其他题。

### GEN-01 单步撤销与通关成绩提交边界

- 类别：0-1。目标：把已经走出的步连同机关状态逐级撤回去，并规定撤过通关瞬间时目录成绩怎么处理。
- 基线：无历史栈；通关当下写入 `records[levelId].bestSteps` 后冻结移动。
- 可复用：`applyMove`、`evaluateGadgets`、蓝图重置、记录表。
- 最强常规方案：每步深拷贝整关运行时；撤销弹出快照；成绩表单独存放。
- 常规方案未解决：快照恢复会把「已通关」一并倒回，与「已完成关的最佳记录仍要能查看」冲突；若成绩表完全不倒回，目录显示已完成而现场未解开，换关规则与「通关才冻结」不再一致。
- 剩余决策：通关记录在「越过通关线的那次撤销」时是撤回、保留、还是等离开本关才提交。
- 反例：20 步通关写入最佳，撤销到 19 步再 25 步打完。若撤销即删记录，目录短时空窗与「已完成最佳」矛盾；若永不撤回，19 步未解状态仍显示已完成且最佳 20，再打 25 步是否更新会错。
- H3：提交时机与快照范围不是代码组织问题，常规深拷贝无法同时满足「现场回到那一步」和「成绩表的已完成语义」。
- P6 预估：调查推动/机关/通关/持久化链路、设计历史范围、接入四模块 UI、验证跨通关撤销与换关清空；高效批量仍 >50。

### GEN-02 最佳路线幽灵分世界

- 类别：0-1。目标：对照自己的最佳步数回放一条残影，同时自己还能继续推。
- 基线：只有最佳步数字段，无走法、无第二份模拟。
- 可复用：关卡蓝图、推动规则、机关求值、记录表。
- 最强常规方案：把最佳走法存在记录里，在同一份文档上重放。
- 常规方案未解决：幽灵与玩家共用踏板/门，残影会改玩家的门；若只画折线不模拟门，残影会穿当前关着的门，对照失真。
- 剩余决策：幽灵世界隔离到什么粒度（整关影子 / 仅坐标折线 / 玩家一动就停），以及重置是清玩家还是连残影一起停。
- 反例：最佳走法曾用木箱压门。玩家把木箱推走后若共用世界，幽灵再踩踏板会把门重新打开，玩家借幽灵作弊；若完全不模拟门，残影走进关着的门，对照无意义。
- H3：隔离范围影响可观察的门与成绩合法性，不是显示层偏好。
- P6 预估：补走法记录、影子模拟、地图双层绘制、进度面板开关、与重置/换关交互；>50。

### GEN-03 冰块滑行的多格一步结算

- 类别：0-1。目标：冰面格子让人或箱一直滑到受阻，整段只记一步，中途经过踏板必须让机关看见。
- 基线：一键一格，无冰，机关只在整步后求值一次。
- 可复用：通行判定、占格、供电求值、步数加一、通关检查。
- 最强常规方案：循环按格移动，每格调用现有 `evaluateGadgets`，步数只加一次。
- 常规方案未解决：滑行开始时人还压在踏板上（基线人不能压板，但箱子可以），离开踏板后门应关上，同时不能把实体停在门里；若按键瞬间冻结通行图，可能停在现已关闭的门内；若逐步重算，可能在同一格被门开关来回弹，一步无法落定。
- 剩余决策：多格一步里「离板关门」与「不可停在门内」的求值相位，以及中途通关检查用哪一格的快照。
- 反例：箱子从踏板滑向曾打开的门。逐步求值会在第二格关门并把箱子卡在门缝；冻结求值会让箱子穿过已应关闭的门。两种常规补丁互斥。
- H3：多格原子步与即时机关之间的相位协议，补一个循环或补一个快照都不能同时满足。
- P6 预估：新地形、滑行循环、机关相位、步数/通关/重置、多关地图数据；>50。

### GEN-04 成对传送与同格冲突

- 类别：0-1。目标：成对传送门，人或箱踏入一端出现在另一端；推动导致箱与人在同一步都可能传送。
- 基线：无传送，移动是邻格替换。
- 可复用：占格、通行、整步后机关、步数。
- 最强常规方案：移动结束后若实体在传送格则写入对端坐标。
- 常规方案未解决：推箱进入传送格时箱子先走、人后踏上被腾空的入口，会连续双传送；若同时传送，对端可能被另一实体占用。出口被关门封住时是取消整步还是只取消传送。
- 剩余决策：同一步内传送的顺序/原子性，出口不可用时的回滚范围（整步 / 只留在入口 / 箱子进门人留下）。
- 反例：人推箱进入 A，B 出口空。先后传送则人跟着进 B 叠箱；整步回滚则看起来踏空；只传箱子则人停在入口，下一步会再传。三种结果都可找到支持理由，题面约束相遇后必须选协议。
- H3：同一步双实体与出口门状态的提交边界。
- P6 预估：传送数据、冲突解析、地图绘制、失败回滚与步数、机关出口门；>50。

### GEN-05 成绩档案导出导入与半局冲突

- 类别：0-1。目标：把已完成最佳记录打成文件带走，也能读回来；损坏文件不得覆盖现场。
- 基线：仅 localStorage 记录表，无半局，无文件。
- 可复用：记录表形状、当前关 id、重置加载蓝图。
- 最强常规方案：JSON 导出整份 `records`，导入覆盖。
- 常规方案未解决：文件带「某关更好成绩」同时带「另一关未完成半局」（若实现者选择把半局一并打包）。覆盖会丢掉本地已完成的关；合并取 min 会留下文件里过期半局去覆盖正在玩的关。基线没有半局，题面会要求「可选地带走当前未完成现场」，使记录与现场所有权冲突。
- 剩余决策：导入是替换、按关合并，还是记录合并但拒绝指纹不匹配的半局；半局与已完成记录同时指向同一关时谁作废。
- 反例：本地关 2 已以 18 步完成，文件含关 2 的 40 步半局和关 1 的更好成绩。整表覆盖丢失 18；只合并数字留下半局把关 2 现场打回未完成且步数 40。
- H3：跨关记录与现场尝试的所有权协议，不是校验函数。
- P6 预估：文件编解码、版本校验、合并策略、目录/地图/步数同时切换、损坏保留；>50。

### GEN-06 限时与步数双成绩在离开地图时的时钟

- 类别：0-1。目标：每关有时限，目录同时展示最佳用时与最佳步数；超时不能写成步数最佳。
- 基线：无时钟，成绩只有步数。
- 可复用：通关提交、重置、目录。
- 最强常规方案：`performance.now()` 累加，通关时写两个字段。
- 常规方案未解决：打开目录看成绩时现场不能被偷偷判负，但若完全冻结，回来后应用墙上时间会立刻超时；若用游戏内步进计时，不走动就不会超时，与「限时」直觉冲突。基线无暂停出口。
- 剩余决策：离开舞台（看目录、看记录）时时钟冻结、后台继续还是把离开时段记为观赛豁免但恢复后补齐。超时与同帧通关谁优先。
- 反例：剩余 0.4 秒打开目录停留 10 秒。后台计时回来即失败且可能写脏成绩；冻结则玩家用目录暂停作弊。必须定义离开舞台的时间所有权。
- H3：双成绩提交与无暂停产品的时钟所有权。
- P6 预估：计时器、双记录结构、目录交互、超时失败不写步数、重置；>50。

### GEN-07 巡逻守卫与踏板抢回合

- 类别：0-1。目标：玩家每走一步后守卫按路线走；撞上失败；失败不得写通关记录；守卫能压踏板。
- 基线：只有玩家与箱子是活动实体，踏板只认箱子种类。
- 可复用：通行、供电、重置、通关提交。
- 最强常规方案：玩家移动后按路径走守卫，再碰撞检测。
- 常规方案未解决：求值次数。若只在玩家移动后求值一次，守卫压上踏板开的门要到下一步才开，守卫会走进仍关着的门；若守卫移动后再求值，玩家可能在同一回合被刚打开的门放行或被刚关上的门夹死。玩家与守卫对换格子是穿越还是死亡。
- 剩余决策：一回合内「玩家移动 / 机关 / 守卫移动 / 机关 / 碰撞 / 通关」的相位，以及守卫算哪类压板物。
- 反例：守卫铁块踩铁板开门。一次求值则守卫卡在门外像迷路；两次求值则玩家可借守卫同回合开门穿过去。对换格子若算安全穿越可躲碰撞。相位选择改变失败与通关。
- H3：新活动体接入供电与胜负的回合协议。
- P6 预估：守卫数据、路线、碰撞、供电种类扩展、失败态与记录隔离、绘制；>50。

### GEN-08 检查点地砖与重置语义

- 类别：0-1。目标：踩检查点后重置可选回到检查点或关卡起点；目录最佳必须是从真正起点算的全程步数。
- 基线：重置总是蓝图起点；步数只有一个计数器。
- 可复用：蓝图 hydrate、重置入口、记录表。
- 最强常规方案：检查点存一份现场拷贝，重置加载该拷贝并把步数清零。
- 常规方案未解决：清零后通关写入的「最佳步数」会变成检查点后的短程，污染目录；若不清零，界面步数含检查点前，和「重置」的直觉冲突。检查点是否包含机关锁定、是否在通关冻结后仍可踩。
- 剩余决策：检查点快照保存哪些字段，显示步数与提交步数是否用两套计数，二次检查点覆盖还是栈。
- 反例：30 步踩检查点，重置后 5 步通关。拷贝+清零会把最佳写成 5；不存箱子只存坐标会丢门状态导致检查点不可复现。
- H3：重置入口被复用后的成绩口径，不是多一个存档键。
- P6 预估：检查点快照、双计数、重置 UI 选择、记录提交、地图标记；>50。

### GEN-09 激光反射与「这步推是否合法」

- 类别：0-1。目标：发射器射出直线光，玻璃反射、铁阻挡、木点燃消失；光打到光闸则开门。
- 基线：门只由踏板供电。
- 可复用：占格、通行、整步供电、通关。
- 最强常规方案：每步结束后扫描光线，把光闸当作额外电源。
- 常规方案未解决：推动玻璃进入光路的那一步，门是推之前关着的。若先判通行再更新光，这步不能穿过将因这次推动而打开的光闸；若先假设推成功再算光再承认移动，可能穿过一扇在推的中途仍关着的门。木箱被点燃发生在移动中还是之后，影响占格。
- 剩余决策：光路相对推动的提交相位，烧毁与通关谁先结算。
- 反例：把玻璃推到反射位才能打开前方光闸，而玻璃的落点就在闸后一格。先通行则永远推不进去；先光路则实体穿过仍关的闸。必须定义「因本步产生的光」能否授权本步。
- H3：新电源与移动合法性的循环依赖。
- P6 预估：光路几何、箱子种类效果、光闸接入供电、绘制、烧毁与胜负；>50。

### GEN-10 双角色轮换与共用踏板

- 类别：0-1。目标：两名可切换操作的角色，各走各的，都能推箱；两人不能叠格。
- 基线：单一 `player` 坐标。
- 可复用：推动、通行、踏板（仍只认箱子）、步数、通关。
- 最强常规方案：数组两人，`activeIndex`，现有 `applyMove` 对当前人调用。
- 常规方案未解决：非活动角色算障碍还是可被推的「箱子」；切换是否计步；两人分别站在将被封道改变的格上时，切换本身会不会触发结算。通关是否要求两人都在某类格。
- 剩余决策：非活动角色的实体类别（障碍 / 可推 / 可压板），以及切换与移动是否同一套提交。
- 反例：把非活动角色当墙，则无法让同伴去压需要「人」的新规则（题面要求两人都能推箱并占位）；当箱子推，则可能把同伴推进缺口且不计「操作步」。切换不计步时玩家可免费调整谁去面对即将关闭的门。
- H3：第二主体在占格、推动、步数三类归属上不能同时沿用单人模型。
- P6 预估：实体模型、切换 UI、推动冲突、地图双角色、通关条件；>50。

### GEN-11 管道洪水蔓延与箱子存亡

- 类别：0-1。目标：打开通水闸后水沿地板蔓延；木箱被冲走，铁箱留下当坝，人踩水失败。
- 基线：地板形态只有架桥/封道，无蔓延，箱子不会消失。
- 可复用：供电、占格、重置、通关提交。
- 最强常规方案：每步对相邻地板做一次 BFS 扩张。
- 常规方案未解决：同一步里人走向即将被淹没的格、铁箱刚被推到决口。先移动后蔓延则人可以走进下一步才到的水；先蔓延后移动则那步在按键时看起来是干地却被拒绝。木箱消失是否立刻改变踏板供电从而关掉水源，形成一步内的振荡。
- 剩余决策：蔓延相对移动的相位，以及水源被自己冲掉木箱后是否在本步切断。
- 反例：木箱压着通水板，水冲走木箱。若本步切断，洪水只出现一格闪一下；若本步不切断，木箱已不在记录里但水仍按「曾供电」扩一轮，现场与供电定义不一致。
- H3：破坏性蔓延与供电的自指，补一次 BFS 不够。
- P6 预估：水格状态、种类破坏、失败/通关、绘制、重置蓝图恢复箱子；>50。

### GEN-12 中途挂起换关再续

- 类别：0-1。目标：把当前未完成现场挂起，去打另一关，再回来从挂起点继续；挂起不得改别关最佳。
- 基线：换关直接丢弃现场，存储只有记录和关卡 id。
- 可复用：hydrate、记录表、重置（应只清当前关）。
- 最强常规方案：`localStorage` 再存一份 `suspendedByLevel`。
- 常规方案未解决：挂起期间该关被写入更好成绩（例如文件导入题不能依赖，这里指同关在目录里用「已完成最佳」对照）。更关键：回来时若蓝图与挂起快照的箱子种类/机关 id 对齐失败怎么办。重置当前关应丢掉该关挂起还是当成「回到挂起」。换关时未挂起就离开是自动挂起还是丢弃（基线是丢弃，本题要改语义）。
- 剩余决策：离开未完成关的默认动作（自动挂起 / 明确按钮才挂起 / 丢弃并确认），以及挂起快照与后来更好成绩并存时目录状态机。
- 反例：关 1 挂在 12 步未解，去关 2 打完。回来关 1 若当新开则丢失 12 步现场；若自动恢复但目录把关 1 标成进行中覆盖「从未完成」还好——若玩家曾通关关 1 又重置挑战，挂起可能把已完成标记打回未完成。
- H3：半局所有权与已完成标记的双状态，不是多一个存储键。
- P6 预估：快照结构、换关协议、重置 vs 挂起、目录徽章、持久化；>50。

### FEAT-01 目标格认箱子种类

- 类别：Feature。现状：任意箱子压在任意目标格都算填满。
- 扩展：部分目标只认指定种类；旧关无种类标记的目标保持任意箱子。
- 最强常规方案：目标格加可选 `accept`，通关检查过滤。
- 常规方案未解决：错误种类的箱子压在认种目标上时，这格对踏板仍可能供电，对通关却不算。若把「占用目标」和「满足目标」合成一个布尔，会关掉压在错误目标上的门。旧存档没有 accept 字段。
- 剩余决策：错误压占是阻挡、可再被推走但不计通关，还是立刻弹开；通关检查与供电是否共用占格函数。
- 反例：铁箱压在只认木的目标上，该格下面是铁板。若占用即满足，错箱也能通关；若占用即不供电，铁门该开却不开，关卡死锁。
- H3：通关谓词与供电谓词从基线的同一占格里拆开。
- 五文件：类型、通关、供电、地图绘制目标标记、目录说明。不能只改 `goalsSatisfied`。

### FEAT-02 连环推箱的中间机关结算

- 类别：Feature。现状：前方有箱子则只有那一只可被推，第二只当墙。
- 扩展：一条直线上的箱子可一起被推，末格有空位即可。
- 最强常规方案：收集整列，一次性平移。
- 常规方案未解决：列上混种箱子会在同一键经过不同踏板。一次性平移后求值，中间「离开踏板、另一箱尚未到达」的断电不会发生；逐只移动并求值，门可能在链条中段关上，导致后半列卡在非法格。两种都能说符合「整步」。
- 剩余决策：连锁移动相对机关的相位（原子平移 / 从近到远逐只 / 从远到近）。
- 反例：两箱一列，前箱离开木板后门应关，后箱落点在门后。原子平移后两箱都过门，门再关，人已把后箱送进门后；逐只则后箱面对关着的门，整步应失败回滚。题面若同时要求「离开踏板要立刻反映在门上」和「能推成列」，协议必须取舍。
- H3：把「一格一实体」扩展成列之后，现有整步一次求值不再充分。
- 五文件：推动、占格、机关求值入口、步数（成功才加）、地图表现。

### FEAT-03 门延迟充能

- 类别：Feature。现状：踏板供电当帧开门。
- 扩展：有的门要连续供电若干步才开，断电策略需定义。
- 最强常规方案：门上加 `charge`，每步 `powered ? charge++ : charge=0`。
- 常规方案未解决：断电是清零、暂停还是每步衰减；充能中途重置本关；通关冻结后是否继续充能（基线通关后不能移动，但若看目录再回来）。与步数簿的「步」是否同一计数。
- 剩余决策：断电曲线，以及充能是否在通关冻结期间推进。
- 反例：差一步充满时打开目录停留。若充能绑墙上时间则偷偷开；若绑步数则离开不推进。差一步时重置：清零才符合「重置现场」，但若 charge 写进记录对照会错。
- H3：新相位与基线「无时钟、通关冻结」相遇。
- 五文件：机关类型、求值、面板显示充能、步数回合钩子、关卡数据。

### FEAT-04 关卡解锁与练习不写成绩

- 类别：Feature。现状：所有关可点，任何通关都写最佳。
- 扩展：需按顺序解锁；可练习未解锁关但不写目录最佳，也不得因此解锁下一关。
- 最强常规方案：`unlocked` 集合，练习模式标志，提交时判断。
- 常规方案未解决：练习通关后现场冻结像正式通关；重置、最佳对照、从练习切回正式是否保留现场。已完成关再练更差成绩不得覆盖。查看已完成最佳仍要在锁定关列表里可见。
- 剩余决策：练习与正式是否两份现场，以及练习通关的冻结/提交入口是否复用正式函数。
- 反例：练习打出 10 步，正式最佳是 18。若共用提交入口会覆盖成 10 并错误解锁；若练习完全不冻结，玩家以为没过。目录必须同时显示锁、可看的旧最佳、练习徽章。
- H3：同一通关函数的写入权限，不是加锁图标。
- 五文件：进度存储、目录 UI、通关提交、重置、地图入口提示。

### FEAT-05 步数拆为空走与推动且迁移旧成绩

- 类别：Feature。现状：只有一个总步数，记录只存它。
- 扩展：区分空走到推动，目录展示两项；旧存档只有总数。
- 最强常规方案：两个计数器，和等于总步。
- 常规方案未解决：最佳记录比的是总数、推动数还是双关键字。旧 18 步无拆分，迁移后缺项。重置清两项；通关冻结时最后一步若是推动必须同时进两项。
- 剩余决策：比较函数与迁移缺省（把旧总数全算空走 / 全算推动 / 只保留总数不参与新排序）。
- 反例：旧最佳 18。新规则按推动数排序。若把 18 全当推动，新的 20 总/4 推动反而「不如」旧档；若旧档不参与排序，目录会暂时没有「最佳」。选择改变可见名次。
- H3：新口径与旧存档比较键。
- 五文件：移动结果分类、步数模型、持久化迁移、目录、通关提交。

### FEAT-06 封道可吞实体且与通关同时发生

- 类别：Feature。现状：封道激活后新走入禁止，已在格上的实体仍可离开。
- 扩展：封道激活时格上的木箱销毁、人失败；铁箱支撑使该格本步不封。
- 最强常规方案：求值末尾扫描封道格的占格并删除木箱。
- 常规方案未解决：销毁木箱可能关掉导致封道的踏板，封道应不应该在本步生效；最后一只木箱被吞的同时其他箱填满目标，失败与通关同帧。
- 剩余决策：吞箱、供电回退、胜负的结算顺序。
- 反例：木箱既压着触发封道的踏板，又是最后一个未进目标的箱子。先吞则失败且目标其实已空；先通关则记录写入后箱子才消失，目录有成绩但现场失败。铁箱支撑若只看求值前占格，推铁箱进入封道格的同一步能否救命。
- H3：破坏与通关共用一次求值出口。
- 五文件：机关求值、箱子生命周期、胜负、地图消失表现、进度失败不写记录。

### FEAT-07 单向地板对人与箱子不同

- 类别：Feature。现状：移动无朝向，四向等价。
- 扩展：单向箭头格；人只能顺箭走，箱子可否逆箭被推是关键冲突。
- 最强常规方案：记录 facing，箭头格过滤方向。
- 常规方案未解决：若箱子与人同一规则，则无法用逆推把箱子顶上箭头当垫块；若箱子无视箭头，人可躲在箱子后被推上逆箭（人没自己走上逆箭）。重置后面向；通关冻结时面向是否保留到重置前展示。
- 剩余决策：箱子、人、被推的人（若将来双角色不依赖本题）三者的箭头谓词是否同一函数。
- 反例：人站在箭头格想逆向离开，前方有箱。若先判人的方向则不能推；若推箱不看人朝向，人保持逆箭站在原格（没动）还是跟着非法移动。基线推箱时人一定走进箱子原格，会被迫逆箭。
- H3：推箱这个「人必走进箱原格」的基线契约与单向约束冲突。
- 五文件：朝向状态、推动合法性、通行、绘制箭头、重置朝向。

### FEAT-08 通关后允许继续推但不回写更差成绩

- 类别：Feature。现状：通关立即冻结移动，最佳已写入。
- 扩展：通关后仍可推，打乱现场；再达成更少步数才更新最佳；更多步数不得回写；重置仍回蓝图。
- 最强常规方案：去掉冻结，每次满足目标就 `min` 写入。
- 常规方案未解决：通关后继续走会离开目标，状态从 cleared 回到 playing 吗？目录已完成标记能否因离开目标被摘掉？步数持续增加时，「本次尝试最佳」与「生涯最佳」两套。
- 剩余决策：cleared 是粘性标记还是现场谓词；继续推时步数簿展示哪一个。
- 反例：18 步通关写入，再走 2 步离开目标。若 cleared 掉了，目录未完成但生涯最佳还在，和基线「已完成才能看最佳」的展示假设冲突；若保持 cleared 且 20 步再填满又 `min`，不会变差——但若错误用最后一次满足覆盖就会变成 20。
- H3：完成标记的粘性与记录更新入口。
- 五文件：尝试状态机、提交函数、步数 UI、目录徽章、移动入口解冻。

### FEAT-09 通关还需机关终态

- 类别：Feature。现状：只检查目标格都有箱子。
- 扩展：部分关要求通关瞬间指定门开着或封道保持。
- 最强常规方案：蓝图加 `clearWhen`，通关函数加条件。
- 常规方案未解决：最后一步同时把箱子推进目标并离开踏板。若先检查目标再求值机关，门还开着会误通关；若先求值再检查，门已关不能通关。两者都与「看到的那一帧」可能不一致。
- 剩余决策：通关判定使用求值前快照、求值后状态，还是要求两帧稳定。
- 反例：最后一箱从踏板被推上目标，门要求保持开。先目标后机关会通关但门随即关上；先机关后目标则永远不能用这步过关，关卡可能无解。必须规定「通关瞬间」的定义。
- H3：把胜负从单一谓词变成与机关求值相位耦合。
- 五文件：蓝图条件、通关、机关求值顺序、面板列出未满足终态、目录。

### FEAT-10 同一扇门被正反踏板争夺

- 类别：Feature。现状：多块踏板对同一门是或开；门默认关，有电则开。
- 扩展：踏板可配置为开门或关门；同一门可被正反来源同时供电。
- 最强常规方案：`open = default XOR positives OR …` 之类布尔式。
- 常规方案未解决：正反同时为真时的合成（开优先、关优先、默认、保持上一帧）。保持上一帧会引入记忆，重置和换关必须定义初值；开优先会让反踏板在正踏板仍压着时无效，关卡作者以为能锁门。
- 剩余决策：冲突合成函数，以及记忆模式是否算「供电状态」要显示在面板。
- 反例：正踏板木箱、反踏板铁箱同时压着。开优先则门开，铁箱「关门」无效；关优先则木箱开门无效；保持上一帧则取决于谁先压上，重放同一步序在「先重置再摆」时结果不同。
- H3：从或开扩展到争夺后，无记忆布尔与有记忆锁存都合理但成绩可复现性不同。
- 五文件：踏板极性、求值、面板列出冲突、关卡数据、通行。

### FEAT-11 拉取箱子与踏板占格交接

- 类别：Feature。现状：只能把箱子向外推，人走进箱子原格。
- 扩展：可向后拉，箱子进入人的原格，人退到身后一格。
- 最强常规方案：检查身后可通行，交换人与箱。
- 常规方案未解决：人原格是踏板时，交换过程是否出现空一帧断电。身后一格是门，门的开关又取决于这次交换是否保持踏板占用。原子交换则门不断；先走人后移箱则闪断，可能让身后门关上导致整步非法。
- 剩余决策：拉步的占格提交是交换还是两段移动，以及失败回滚。
- 反例：人站在木板上拉前方木箱，身后是由该板打开的门。两段移动会闪关使拉失败；原子交换则门一直开，拉成功。题面若要求「箱子马上补上则门不闪」同时又用「身后门按最新供电检查合法性」，必须选协议。
- H3：基线「人必进箱格」被拉反过来后，现有一次求值不够描述中间占格。
- 五文件：推动库扩展、通行、机关、步数分类、操作说明 UI。

### FEAT-12 边沿自锁踏板与电平踏板共存

- 类别：Feature。现状：踏板是电平：箱子在则供电，离开则断电。
- 扩展：部分踏板改为进入边沿翻转锁存；同一门可同时连到电平板和自锁板。
- 最强常规方案：踏板加 `mode`，边沿检测 `wasOccupied`。
- 常规方案未解决：与电平板争夺同一门时，锁存记忆和电平实时值如何合成（接 FEAT-10 但不能依赖那题：本题必须在基线或开模型上自洽）。重置必须清锁存；换关清；通关冻结后箱子被…不能继续移动。同一箱子在自锁板上微微「走了又回来」是否两次边沿。基线一格一步没有微动，但推到板上再推走再推回是两次。
- 剩余决策：自锁状态存在踏板、门还是尝试层；与电平或合成时是否让锁存充当第三电源。
- 反例：自锁已翻开，电平板断电。若或开，门保持开，关卡无法用离开电平板来关门；若锁存只在无电平冲突时生效，作者配置的自锁会被电平板覆盖。重置后锁存应关，但若存在文档里会串关。
- H3：两种时间语义接到同一扇门，基线纯电平或门不够。
- 五文件：踏板模式、边沿、求值、面板锁存指示、重置清记忆。
